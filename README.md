# ПроКод — сайт детской онлайн-школы программирования

Лендинг для родителей + админ-панель для обработки заявок. Работает локально одной командой,
без базы данных и внешних сервисов.

- **Лендинг** — <http://localhost:3000/>
- **Админ-панель** — <http://localhost:3000/admin>

---

## Быстрый старт

Нужен [Node.js](https://nodejs.org/) версии 18 или новее (проверено на 24).

```bash
cd "C:\Users\Ярослав\Documents\Cloude works\ProCode"

npm install        # поставить зависимости (один раз)
npm run css        # собрать стили в public/css/styles.css
npm run seed       # добавить 10 демо-заявок, чтобы админку было на чём посмотреть
npm start          # запустить сервер
```

Откройте <http://localhost:3000/>. Чтобы остановить сервер — `Ctrl + C` в терминале.

**Вход в админ-панель.** Заведены две учётные записи:

| Логин | Кому |
|---|---|
| `Yarichpek375` | владелец |
| `89606225073n.` | менеджер |

Регистр логина не важен: `yarichpek375` тоже подойдёт. Пароли задавали вы — в проекте они
не записаны ни в одном файле (см. раздел «Учётные записи менеджеров»).

## Команды

| Команда | Что делает |
|---|---|
| `npm start` | Запускает сервер на порту 3000 |
| `npm run dev` | То же, но перезапускается при правках файлов сервера |
| `npm run css` | Собирает Tailwind в `public/css/styles.css` |
| `npm run css:watch` | Пересобирает стили на лету — держите запущенным, пока правите вёрстку |
| `npm run seed` | Добавляет 10 демонстрационных заявок |
| `npm run seed:reset` | Очищает базу и добавляет 10 демонстрационных заявок |
| `npm run users` | Показывает список учётных записей менеджеров |
| `npm run user:add -- <логин> <пароль>` | Создаёт менеджера или меняет ему пароль |

> **Важно:** после любой правки классов в HTML запустите `npm run css`.
> Tailwind собирает только те классы, которые нашёл в разметке, — иначе новые стили не появятся.

## Как работают заявки

1. Родитель заполняет форму в конце лендинга.
2. `public/js/form.js` проверяет поля и отправляет `POST /api/applications`.
3. Сервер **заново проверяет всё сам** (клиенту не доверяем), нормализует телефон
   к виду `+7XXXXXXXXXX` и дописывает заявку в `data/applications.json`.
4. Заявка появляется в админ-панели со статусом «Новая». Одновременно она печатается
   в консоль сервера — так вы увидите обращение, даже не заходя в админку.

Файл `data/applications.json` — обычный JSON, его можно открыть, отредактировать или
сделать резервную копию. Запись атомарная и выстроена в очередь, поэтому одновременные
заявки не затирают друг друга. Если файл окажется повреждён, сервер не упадёт: он отложит
испорченную копию рядом (`applications.corrupt-<дата>.json`) и продолжит работу.

### Статусы заявки

`Новая` · `Согласился` · `Думает` · `Перезвонить` · `Недозвон` · `Отказ`

Менеджер меняет статус и пишет свой комментарий в боковой панели, которая открывается
кликом по заявке. Там же кнопка «Позвонить» (`tel:`-ссылка) и удаление заявки.

### Возможности админки

- Плитки-счётчики по каждому статусу — клик фильтрует список
- Поиск по имени родителя, имени ребёнка, телефону, направлению и обоим комментариям
  (телефон ищется без учёта формата: `8916…` найдёт `+7916…`)
- Фильтр по датам и сортировка
- Выгрузка отфильтрованных заявок в CSV для Excel

## Учётные записи менеджеров

Менеджеры хранятся в `data/users.json`. **Паролей в этом файле нет** — для каждого лежит
случайная соль и scrypt-хэш, из которого пароль обратно не достаётся. Файл добавлен
в `.gitignore`, чтобы не попасть в репозиторий.

```bash
npm run users                                  # кто заведён
npm run user:add -- ivan МойПароль123          # создать или сменить пароль
node scripts/manage-users.js --remove ivan     # удалить
```

Пароль можно не писать в командной строке — он попадает в историю оболочки. Надёжнее
передать его через стандартный ввод:

```bash
echo "МойПароль123" | node scripts/manage-users.js --add ivan
```

Полезно знать:

- Логин сравнивается **без учёта регистра**, пароль — с учётом.
- Проверка пароля намеренно занимает около 50 мс: это делает перебор бессмысленным
  и незаметно для человека.
- Удалили или переименовали учётную запись — её открытые сессии перестают действовать сразу.
- Пока `data/users.json` пуст или отсутствует, вход работает по `ADMIN_LOGIN` и `ADMIN_PASSWORD`
  из `.env`. **Как только заведён хотя бы один менеджер, этот запасной вход отключается** —
  сейчас он уже не работает.
- Один сеанс живёт 12 часов, дальше нужно войти заново.

## Настройка

Все настройки — в файле `.env` в корне проекта:

```ini
PORT=3000
ADMIN_LOGIN=admin
ADMIN_PASSWORD=procode2025
SESSION_SECRET=<длинная случайная строка>
TRUST_PROXY=0
```

- **`ADMIN_LOGIN` и `ADMIN_PASSWORD`** — запасной вход на случай, если `data/users.json` пуст.
  Сейчас заведены две учётные записи, поэтому эти значения не используются. Сервер всё ещё
  предупреждает о стандартном пароле при запуске — предупреждение можно игнорировать, пока
  файл с менеджерами на месте, но лучше задать здесь свой пароль: он понадобится, если файл
  учётных записей будет потерян.
- **`SESSION_SECRET`** — секрет для подписи cookie. Уже сгенерирован случайно.
  Если его удалить, после каждого перезапуска придётся входить в админку заново.
  Сгенерировать новый: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
- **`TRUST_PROXY`** — ставьте `1`, только если сайт стоит за nginx или Caddy. Иначе
  ограничения по IP можно будет обойти подделкой заголовка.

После правки `.env` перезапустите сервер.

## Публикация на сервере

Проект — обычное Node-приложение, разворачивается на любом VPS:

1. Скопируйте файлы, выполните `npm install --omit=dev` и `npm run css`.
2. Создайте `.env` с рабочим паролем и секретом.
3. Поднимите процесс через `pm2`, `systemd` или Docker.
4. Поставьте перед ним nginx с HTTPS и укажите `TRUST_PROXY=1`.
5. Настройте резервное копирование `data/applications.json` — это единственное место,
   где живут заявки.

## Технические решения

- **Node.js + Express**, зависимость ровно одна — сам Express. Авторизация, разбор cookie
  и парсер `.env` написаны на стандартной библиотеке, чтобы не тащить лишнее.
- **Хранилище — JSON-файл.** Этого достаточно для нескольких тысяч заявок. Дальше стоит
  перейти на SQLite: менять придётся только `server/store.js`.
- **Tailwind CSS 3** со своей дизайн-системой в `src/input.css`: чернильно-синий `#0F1222`,
  кобальт `#2B4BF2`, тёплый абрикосовый акцент `#FF9E64`. Шрифты — Unbounded (заголовки),
  Onest (текст), JetBrains Mono (цифры и код).
- **Защита:** серверная валидация всех полей, ловушка для ботов, блокировка перебора пароля,
  подписанная HttpOnly-cookie, сравнение секретов за постоянное время, экранирование формул
  при выгрузке в CSV, заголовки `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`
  и `Referrer-Policy`. Данные пользователей попадают в интерфейс только через `textContent` —
  внедрить скрипт через заявку нельзя.
- **Два ограничителя частоты по IP** на форме заявки: 5 успешных заявок за 10 минут и
  30 любых обращений за те же 10 минут. Второй нужен, чтобы поток заведомо неверных запросов
  тоже упирался в предел, а не оставался бесплатным для бота.
- **Доступность:** страница работает с клавиатуры, у элементов видимый фокус, FAQ собран
  на нативных `<details>` и раскрывается без JavaScript, анимации отключаются при
  системной настройке «уменьшить движение».

## Известные ограничения

- Счётчики ограничения частоты и неудачных входов живут в памяти: после перезапуска сервера
  обнуляются. Для одного небольшого сайта этого достаточно.
- Список заявок перечитывает файл на каждый запрос — нормально до нескольких тысяч записей.
- Удаление заявки безвозвратное, «корзины» нет (перед удалением спрашивается подтверждение).
- Вёрстка проверена в браузере на движке Chromium при ширинах 500–1440 px. Ниже 500 px
  headless-браузер в этом окружении принудительно расширяет окно, поэтому диапазон
  320–500 px стоит один раз просмотреть глазами на реальном телефоне.
