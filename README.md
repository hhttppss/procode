# ПроКод — сайт и внутренняя платформа школы

Лендинг для родителей + внутренняя CRM для школы: заявки, ученики, преподаватели,
расписание и финансы. Работает локально одной командой, без базы данных и внешних сервисов.

- **Лендинг** — <http://localhost:3000/>
- **Платформа** — <http://localhost:3000/app>
- **Вход для сотрудников** — <http://localhost:3000/login>

> Подробная пошаговая инструкция по запуску, включая решение частых проблем, —
> в отдельном файле [**ЗАПУСК.md**](ЗАПУСК.md).

## Быстрый старт

Нужен [Node.js](https://nodejs.org/) версии 18 или новее (проверено на 24).

```bash
cd D:\ProCode

npm install        # поставить зависимости (один раз)
npm run css        # собрать стили в public/css/styles.css
npm run seed       # демо-данные: ученики, расписание, финансы, преподаватели
npm start          # запустить сервер
```

Откройте <http://localhost:3000/>. Чтобы остановить сервер — `Ctrl + C` в терминале.

**Вход в платформу.** Заведены две учётные записи администратора:

| Логин | Кому | Роль |
|---|---|---|
| `Yarichpek375` | владелец | Администратор |
| `89606225073n.` | менеджер | Администратор |

Регистр логина не важен: `yarichpek375` тоже подойдёт. Действующие пароли —
в файле [ЗАПУСК.md](ЗАПУСК.md), раздел 3; после первого входа смените их в разделе
**Профиль → Смена пароля**.

Команда `npm run seed` дополнительно создаёт трёх демо-преподавателей — `orlova`, `kim`,
`volkova`, пароль у всех `demo12345`. Под ними удобно посмотреть, как выглядит система
для роли «Преподаватель». Перед выходом «в бой» их стоит удалить.

## Роли и права

| Что | Администратор | Преподаватель |
|---|---|---|
| Заявки с сайта | полный доступ | нет доступа |
| Ученики | полный CRUD, все поля | только свои, только просмотр |
| Контакты родителей, оплаты, заметки администрации | видит | **не видит** |
| Преподаватели и ставки | полный доступ | нет доступа |
| Расписание | создаёт, переносит, удаляет | видит своё, отмечает итог занятия |
| Финансы | полный доступ | нет доступа |
| Свой профиль | да | да, но без ставки |

Разграничение сделано на трёх уровнях, а не только скрытием кнопок:

1. **Маршруты страниц** (`server/routes/pages.js`) — преподаватель, открыв `/app/finance`,
   получает переадресацию на главную. В его HTML нет и самих ссылок на закрытые разделы.
2. **Маршруты API** (`server/routes/api/index.js`) — модули «Заявки», «Преподаватели»
   и «Финансы» закрыты целиком: прямой запрос вернёт `403`.
3. **Поля ответа** (`server/domain/access.js`) — телефон родителя, история оплат, заметки
   администратора и ставка **физически отсутствуют** в JSON, который получает преподаватель.
   Выборки тоже строятся по `req.user.id`, а не по идентификатору из запроса, поэтому чужого
   ученика или чужое занятие нельзя запросить даже вручную.

Заблокированный сотрудник теряет доступ немедленно: право проверяется по свежей записи
из `data/users.json`, а не по содержимому cookie.

## Модули

**Главная.** У администратора — ученики, заявки за период, преподаватели, оборот, занятия,
разрезы по направлениям и статусам. У преподавателя — ближайшее занятие с кнопкой
«Подключиться», список занятий без отметки об итоге и своя статистика.

**Заявки** (только администратор). Воронка `Новая → В обработке → Назначено вводное →
Ученик зачислен / Отказ`, поиск (в том числе по телефону без учёта формата), фильтры по дате
и статусу, история изменений по каждой заявке, выгрузка в CSV. Кнопка «В ученики» переносит
данные в новую карточку; статус «Ученик зачислен» иначе поставить нельзя — так заявка
и карточка не расходятся. О новой заявке администраторы узнают из колокольчика в шапке.

**Ученики.** Карточка: имя и возраст, направление, группа, преподаватель, особенности
(темп, поведение, здоровье, пожелания), статус, посещаемость и прогресс — это видят обе роли.
ФИО и контакты родителей, история оплат и заметки администратора — только администратор.
Фильтры по направлению, преподавателю, статусу и возрасту, счётчики по направлениям,
история изменений карточки с указанием, кто и что поменял.

**Преподаватели** (только администратор). Создание учётной записи с логином и паролем,
блокировка, смена пароля, ставка, направления, список закреплённых учеников и статистика
занятий. Последнего активного администратора система не даст ни разжаловать, ни заблокировать.

**Расписание.** Администратор: календарь день / неделя / месяц, создание занятий, в том числе
повторяющихся (дни недели + дата окончания, до 200 занятий за раз), перенос, удаление занятия
или всей серии. Преподаватель: виды день и неделя, только свои занятия, отметка
«проведено / отменено / перенесено», комментарий по итогам и посещаемость каждого ученика.
О любом изменении расписания преподаватель получает уведомление.

**Финансы** (только администратор). Оборот за период, оплаты учеников, расходы, график
доходов и расходов, отчёт по занятиям в разрезе преподавателей. Начисление считается
автоматически — ставка × число проведённых занятий за период; кнопка «Начислить» превращает
расчёт в запись расхода, повторно за тот же период начислить нельзя.

## Команды

| Команда | Что делает |
|---|---|
| `npm start` | Запускает сервер на порту 3000 |
| `npm run dev` | То же, но перезапускается при правках файлов сервера |
| `npm run css` | Собирает Tailwind в `public/css/styles.css` |
| `npm run css:watch` | Пересобирает стили на лету — держите запущенным, пока правите вёрстку |
| `npm run seed` | Добавляет демо-данные ко всем модулям |
| `npm run seed:reset` | Очищает рабочие данные (кроме учётных записей) и создаёт демо заново |
| `npm run users` | Показывает список сотрудников |
| `npm run user:add -- <логин> <пароль>` | Создаёт администратора или меняет ему пароль |

> **Важно:** после любой правки классов в HTML или в клиентском JavaScript запустите `npm run css`.
> Tailwind собирает только те классы, которые нашёл в исходниках, — иначе новые стили не появятся.

## Как проверить систему под разными ролями

1. `npm run seed:reset` — чистые демо-данные и три преподавателя.
2. `npm start`, открыть <http://localhost:3000/login>.
3. **Под администратором** (`Yarichpek375` или своя учётка):
   - на «Главной» видны все шесть плиток и оборот;
   - в «Заявках» откройте любую, поменяйте статус, нажмите «В ученики»;
   - в «Учениках» откройте карточку — видны родители, оплаты и история;
   - в «Расписании» нажмите «Новое занятие», включите «Повторять еженедельно»;
   - в «Финансах» нажмите «Начислить» напротив преподавателя.
4. Выйдите и войдите **под преподавателем** (`orlova` / `demo12345`):
   - в меню только «Главная», «Ученики», «Расписание», «Профиль»;
   - в списке учеников — трое, а не десять;
   - в карточке ученика нет блоков «Родители и контакты», «История оплат» и кнопки
     «Редактировать»;
   - в «Расписании» нет кнопки «Новое занятие» и вида «Месяц»; в окне занятия доступны
     только итог, комментарий и посещаемость;
   - в «Профиле» нет строки со ставкой.
5. Проверка «в лоб», без интерфейса — прямые запросы к API должны отвечать `403`:

```bash
# войти преподавателем и сохранить cookie
curl -c t.cookie -X POST http://localhost:3000/login \
  -H "Content-Type: application/json" \
  -d '{"login":"orlova","password":"demo12345"}'

curl -b t.cookie http://localhost:3000/app/api/applications      # 403
curl -b t.cookie http://localhost:3000/app/api/finance/summary   # 403
curl -b t.cookie http://localhost:3000/app/api/teachers          # 403
```

## Хранение данных

Каждая коллекция — отдельный JSON-файл в `data/`:

| Файл | Что внутри |
|---|---|
| `users.json` | сотрудники: логин, роль, ФИО, контакты, направления, ставка, доступ |
| `applications.json` | заявки с сайта, статус, комментарии менеджера, история |
| `students.json` | карточки учеников, включая данные родителей |
| `lessons.json` | занятия: дата, время, преподаватель, ученики, формат, ссылка, итог, посещаемость |
| `payments.json` | оплаты учеников |
| `expenses.json` | расходы, включая начисления преподавателям |
| `notifications.json` | уведомления в интерфейсе |
| `audit.json` | история изменений карточек и учётных записей |

Общие свойства всех файлов: запись атомарная (временный файл + переименование), изменяющие
операции выстроены в единую очередь, чтение кэшируется по времени изменения файла. Повреждённый
файл не роняет сервер — он откладывается рядом как `<имя>.corrupt-<дата>.json`, работа
продолжается с пустым списком.

Файлы можно открыть и отредактировать вручную — сервер подхватит правки без перезапуска.

При первом запуске старые файлы первой версии проекта обновляются автоматически: учётные
записи получают идентификаторы и роль «Администратор», заявки — статусы новой воронки
(`Думает`, `Перезвонить`, `Недозвон` → `В обработке`; `Согласился` → `Назначено вводное`).

## Как работают заявки

1. Родитель заполняет форму в конце лендинга.
2. `public/js/form.js` проверяет поля и отправляет `POST /api/applications`.
3. Сервер **заново проверяет всё сам** (клиенту не доверяем), нормализует телефон
   к виду `+7XXXXXXXXXX` и дописывает заявку в `data/applications.json`.
4. Заявка появляется в модуле «Заявки» со статусом «Новая», все администраторы получают
   уведомление, а обращение печатается в консоль сервера — так вы увидите его, даже не заходя
   в платформу.

## Учётные записи

Сотрудники хранятся в `data/users.json`. **Паролей в этом файле нет** — для каждого лежит
случайная соль и scrypt-хэш, из которого пароль обратно не достаётся. Файл добавлен
в `.gitignore`, чтобы не попасть в репозиторий.

Преподавателей удобнее заводить в интерфейсе: **Преподаватели → Новый сотрудник**.
Из командной строки доступно то же самое:

```bash
npm run users                                              # кто заведён
npm run user:add -- ivan МойПароль123                      # администратор
node scripts/manage-users.js --add masha Пароль123 --teacher --name "Мария Орлова"
node scripts/manage-users.js --remove ivan                 # удалить
```

Удаление ведёт себя так же, как в интерфейсе: ученики открепляются от сотрудника,
его уведомления удаляются, а при наличии запланированных занятий команда откажется
работать — чтобы расписание не осталось с ссылками в никуда. Снять проверку можно
флагом `--force`.

Пароль можно не писать в командной строке — он попадает в историю оболочки. Надёжнее
передать его через стандартный ввод:

```bash
echo "МойПароль123" | node scripts/manage-users.js --add ivan
```

Полезно знать:

- Логин сравнивается **без учёта регистра**, пароль — с учётом.
- Проверка пароля намеренно занимает около 50 мс: это делает перебор бессмысленным
  и незаметно для человека.
- Удалили или заблокировали сотрудника — его открытые сессии перестают действовать сразу.
- Пока `data/users.json` пуст или отсутствует, вход работает по `ADMIN_LOGIN` и `ADMIN_PASSWORD`
  из `.env`. **Как только заведён хотя бы один сотрудник, этот запасной вход отключается** —
  сейчас он уже не работает.
- Один сеанс живёт 12 часов, дальше нужно войти заново.
- Восемь неудачных попыток входа с одного адреса блокируют вход на 15 минут.

## Настройка

Все настройки — в файле `.env` в корне проекта:

```ini
PORT=3000
ADMIN_LOGIN=admin
ADMIN_PASSWORD=procode2025
SESSION_SECRET=<длинная случайная строка>
TRUST_PROXY=0
```

- **`ADMIN_LOGIN` и `ADMIN_PASSWORD`** — запасной вход на случай, если `data/users.json` пуст.
  Сейчас заведены учётные записи, поэтому эти значения не используются. Сервер всё ещё
  предупреждает о стандартном пароле при запуске — лучше задать здесь свой: он понадобится,
  если файл учётных записей будет потерян.
- **`SESSION_SECRET`** — секрет для подписи cookie. Если его удалить, после каждого перезапуска
  придётся входить заново.
  Сгенерировать новый: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
- **`TRUST_PROXY`** — ставьте `1`, только если сайт стоит за nginx или Caddy. Иначе
  ограничения по IP можно будет обойти подделкой заголовка.

После правки `.env` перезапустите сервер.

## Публикация на сервере

Проект — обычное Node-приложение, разворачивается на любом VPS:

1. Скопируйте файлы, выполните `npm install --omit=dev` и `npm run css`.
2. Создайте `.env` с рабочим паролем и секретом.
3. Поднимите процесс через `pm2`, `systemd` или Docker.
4. Поставьте перед ним nginx с HTTPS и укажите `TRUST_PROXY=1`.
5. Настройте резервное копирование папки `data/` — это единственное место, где живут
   заявки, ученики, расписание и финансы.

## Технические решения

- **Node.js + Express**, зависимость ровно одна — сам Express. Авторизация, разбор cookie
  и парсер `.env` написаны на стандартной библиотеке, чтобы не тащить лишнее. Графики
  в финансах нарисованы обычным SVG, без библиотек.
- **Хранилище — JSON-файлы** через общий движок `server/db.js`. Этого достаточно для школы
  на несколько сотен учеников. Дальше стоит перейти на SQLite: менять придётся только `db.js`.
- **Разграничение прав в одном месте** — `server/domain/access.js`. Там же сериализаторы,
  которые вырезают лишние поля из ответа. Интерфейс не «прячет» данные, их просто нет.
- **Страницы платформы собираются на сервере** по роли, данные подгружает браузер через
  `/app/api/*`. Меню преподавателя не содержит ссылок на закрытые разделы даже в исходном коде.
- **Tailwind CSS 3** со своей дизайн-системой в `src/input.css`: чернильно-синий `#0F1222`,
  кобальт `#2B4BF2`, тёплый абрикосовый акцент `#FF9E64`. Шрифты — Unbounded (заголовки),
  Onest (текст), JetBrains Mono (цифры и код).
- **Защита:** серверная валидация всех полей, ловушка для ботов, блокировка перебора пароля,
  подписанная HttpOnly-cookie с `SameSite=Lax`, проверка заголовка `Origin` на изменяющих
  запросах, сравнение секретов за постоянное время, экранирование формул при выгрузке в CSV,
  заголовки `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`
  и `Referrer-Policy`. Данные попадают в интерфейс только через `textContent` — внедрить
  скрипт через заявку или комментарий нельзя. Ссылки на созвон принимаются только с `http(s)`.
- **Два ограничителя частоты по IP** на форме заявки: 5 успешных заявок за 10 минут и
  30 любых обращений за те же 10 минут.
- **Доступность:** страницы работают с клавиатуры, у элементов видимый фокус, модальные окна
  запирают фокус внутри и закрываются по `Esc`, анимации отключаются при системной настройке
  «уменьшить движение».

## Известные ограничения

- Уведомления живут только внутри интерфейса: почта и мессенджеры не подключены, для этого
  нужны сторонние сервисы и ключи. Страница опрашивает сервер раз в 30 секунд.
- Счётчики ограничения частоты и неудачных входов живут в памяти: после перезапуска сервера
  обнуляются.
- Отдельной сущности «группа» нет: у ученика есть текстовое поле «группа», а занятие просто
  ссылается на нескольких учеников. Для школы такого размера этого достаточно.
- Удаление безвозвратное, «корзины» нет (перед удалением спрашивается подтверждение).
  Вместе с карточкой ученика удаляются его оплаты, и он убирается из всех занятий.
- Вёрстка проверена в браузере на движке Chromium при ширинах 390–1440 px, горизонтальной
  прокрутки нет. Диапазон 320–390 px стоит один раз просмотреть глазами на реальном телефоне.
